# Product Match 開発仕様書 v0.1

## 1．目的

Product Matchを、ユーザーが利用できる機能単位で段階的に実装する。

各機能は、実装・手動動作確認・セキュリティ確認を完了してから`main`へ反映する。

---

## 2．開発の進め方

```text
必要な機能を整理する
↓
優先順位を決める
↓
機能を1つ実装する
↓
手動で動作確認する
↓
権限・不正操作を確認する
↓
mainへ反映する
↓
次の機能へ進む
```

機能は、DBテーブルや画面部品ではなく、ユーザーができることを単位とする。

例：

```text
MakerがProductを登録できる
```

---

## 3．MVP機能一覧

この章は実装対象の一覧であり、番号どおりに一つずつ実装する順序ではない。
実装の優先順位は「6．実装順序」に従う。

### 3.1 アカウント

1. ユーザーが登録・ログインできる
2. ユーザーがプロフィールを編集・閲覧できる

### 3.2 Product管理

3. MakerがProductを登録できる
4. Makerが自分のProductを編集できる
5. AdminがProductを承認・却下できる
6. 承認済みProductがArena参加待ちQueueへ入る

### 3.3 Arena・Match

7. AdminまたはシステムがArenaを生成できる
8. Arena内にMatchとBracketを生成できる
9. ユーザーがMatchを閲覧できる
10. ユーザーがMatchへ1回だけ投票できる
11. Product所有者が自分のMatchへ投票できない
12. Match終了後に勝者を決定できる
13. 勝者から次RoundのMatchを生成できる
14. Final後にArena Championを決定できる
15. ユーザーがArenaのBracketを閲覧できる

### 3.4 発見・コミュニティ

16. ユーザーがProduct詳細・過去戦績を閲覧できる
17. ユーザーがProductへコメントできる
18. Gate Matchへ投票してDiscover画面へ入れる
19. Makerが自分のProduct・Match状況をDashboardで確認できる
20. AdminがArena・Match・ユーザーを管理できる
21. Matchを共有できる
22. ランキングを閲覧できる

### 3.5 運用

23. 定期処理がMatch・Arenaを自動進行できる
24. 不正投票・権限違反を防げる

---

## 4．各機能の完了条件

各機能は、以下をすべて満たした場合に完了とする。

1. 仕様どおりに実装されている
2. ローカル環境で画面操作による手動確認ができている
3. 必要な自動テストを追加し、成功している
4. エラー時の表示または処理を確認している
5. 権限・不正操作への対策を実装・確認している
6. 変更をGitへコミットし、`main`へ反映している

画面の文言・余白だけを変更する場合は手動確認のみでもよい。
一方、認証・権限・DB更新・投票・大会進行を変更する場合は、自動テストを必須とする。

---

## 5．動作確認・セキュリティ確認

この章は最低限の確認例である。記載のない機能でも、実装ごとに同じ観点で確認する。

### 5.1 各機能で行う確認

| 確認 | 内容 |
| --- | --- |
| 手動確認 | 実際に画面を操作し、ユーザーの操作が完了することを確認する |
| 自動テスト | 変更したロジック・DB処理・権限を繰り返し確認できる形にする |
| セキュリティ確認 | 未ログイン操作、他人のデータ操作、管理者操作、不正な入力を確認する |
| 結合確認 | 依存する前後の機能とつないだ状態で確認する |

### 5.2 自動テストの対象

| 対象 | 必須の確認 |
| --- | --- |
| 認証 | 未ログインユーザーを保護画面・操作から拒否できる |
| Product更新 | 所有者以外が更新できない |
| Admin操作 | Admin以外が承認・却下できない |
| 投票 | 1ユーザー1票、自己投票不可、終了後投票不可 |
| Arena進行 | 勝者確定、次Round生成、Champion決定 |
| RLS | 他ユーザーの非公開データを取得・更新できない |

### 5.3 機能ごとの確認例

| 機能 | 手動確認 | セキュリティ確認 |
| --- | --- | --- |
| 登録・ログイン | 登録、ログイン、ログアウトできる | Sessionが他ユーザーへ渡らない |
| Product登録 | 情報・画像を保存できる | 未ログインでは登録できない。所有者以外は編集できない |
| Admin審査 | 承認後にQueueへ追加される | Admin以外は承認・却下できない |
| Arena生成 | QueueからArenaとBracketが生成される | 同一Productを複数Arenaへ入れない |
| 投票 | 票が反映される | 1ユーザー1票、自己投票不可、終了後投票不可 |
| 大会進行 | 次RoundとChampionが生成される | 定期処理を許可なく実行できない |
| コメント | 投稿・表示できる | 未ログイン投稿不可。他人のコメントを編集できない |
| Dashboard | 自分のProductだけ確認できる | 他Makerの分析・管理情報を見られない |

## 6．実装順序

```text
Phase 1：アカウント
↓
Phase 2：Product登録・審査
↓
Phase 3：Arena生成・Match・投票
↓
Phase 4：勝者確定・次Round・Champion
↓
Phase 5：Dashboard・Admin・定期処理
↓
Phase 6：Discover・Gate・コメント・ランキング・共有
↓
Phase 7：デザイン改善・不正対策・運用改善
```

各Phase内では、依存関係のない機能を並行して実装できる。
ただし、`main`へ反映する前に「4．各機能の完了条件」を満たす必要がある。

## 7．ブランチ運用

各機能は、`main`から作成した専用ブランチで作業する。複数の機能を同じブランチで実装してはならない。

```text
feature/auth
feature/product-submission
feature/admin-review
feature/arena-voting
feature/tournament-advancement
```

作業の流れ：

```text
mainからfeature/<機能名>を作成
↓
機能を実装・確認
↓
feature/<機能名>をGitHubへPush
↓
mainへマージ
↓
mainをPush
```

手動確認・自動テスト・セキュリティ確認を完了するまでは、`main`へマージしない。

## 8．MVP公開前の通し確認

以下を最初から最後まで手動確認する。

```text
ユーザー登録
↓
Product登録
↓
Admin承認
↓
Arena生成
↓
別ユーザーによる投票
↓
勝者確定
↓
次Round生成
↓
Champion決定
```

この流れが正常に完了すれば、MVP公開の判断を行う。
